# VTI-as-Challenger — Inverted Gate Cross-Workflow Experiment

## Premise

Across 9 completed youBet ETF/portfolio/stock-selection workflows, **zero** alternative strategies passed their workflow's strict gate against the workflow's native benchmark (100% VTI, 60/40 VTI/BND, SPY, factor B&H, or DBC B&H depending on workflow). The user hypothesized that the universal null-result pattern is at least partly a power problem: short records (typical 9-25 years daily) and modest effect sizes make differences between marginally-different strategies hard to detect.

This workflow **inverts the framing**: for each strategy that previously had a positive point estimate (Sharpe-diff or CAGR-diff > 0 vs the workflow's native benchmark), we test whether the **benchmark passes the inverted gate** against that strategy — i.e., does the benchmark beat the alternative? Two complementary tests are applied:

1. **Sign-flipped one-sided gate** — call `block_bootstrap_test(strategy=benchmark, benchmark=candidate)` so the upper-tail p-value tests H0: "benchmark ≤ candidate"; reject (pass) at p < 0.05.
2. **TOST equivalence test** with per-workflow native MEI — the diff CI is computed at 90% confidence; we declare equivalence iff `-MEI < ci_lower AND ci_upper < +MEI`.

If both tests fail for a candidate, the conclusion is "non-significant in either direction, equivalence cannot be claimed at this MEI" — genuinely power-limited. If sign-flipped fails but TOST passes, we can claim **statistical equivalence under the workflow's native MEI**, which is a stronger and more actionable conclusion than the original null.

## Conventions

- Each candidate uses its workflow's **native benchmark** (not literally VTI everywhere — `__benchmark_60_40__` for commodity, `__bench_SMB__` for factor-timing, `__benchmark__` (SPY) for stock-selection, etc.). This preserves the original gate's intent.
- Each candidate uses its workflow's **native MEI** (sourced from the workflow's `config.yaml` or power-analysis doc).
- Single **joint Holm-N correction** across all 3 reporting classes (statistical family ≠ reporting segmentation).
- All bootstraps use Politis-Romano stationary block bootstrap, 22-day expected block length, 10,000 replicates, deterministic seed.
- Source-period-bias controls (per `feedback_source_period_bias`): placebo + sub-period + linear-scaling applied to **all** candidates uniformly.

## Conventions about excluded workflows

Three workflows (`international-etf`, `macro-exploratory`, `etf`) have **no daily-return parquet artifacts** saved — only summary JSONs/results files. Their candidates are deferred from v1 of this experiment; including them would require re-running the original phase scripts to regenerate daily returns, which is out of scope. Documented in `research/precommit.json::excluded_candidates`.

- `experiments/phase3_robustness.py` — placebo + sub-period + linear-scaling
